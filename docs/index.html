NoireBox v0.23.0

A tamper-evident journal for AI agents: every event hash-chained (SHA-256), signed (Ed25519), append-only on SQLite, anchored to external RFC 3161 witnesses — plus a pluggable guardrail and a standalone verifier a third party can run offline, without trusting you.

pip install noirebox

source · SPECS.md · threat model · changelog · 29 ADRs

§Overview

NoireBox is a single FastAPI service + Python package that gives an AI-agent system two guarantees: provable traceability (every event sealed in a journal a third party can verify offline) and input filtering (transcripts scanned before they reach the agent, verdicts sealed as events). The journal is domain- and language-agnostic — an event is a type and a payload — which is why it fits any stack. The verification never contacts the server: the export plus openssl is the whole trust surface.

Properties

  • Append-only — no UPDATE, no DELETE exist; sealing costs 0.17 ms/event
  • Located tamper detection — rewrite, insert or delete fails verification at the exact seq
  • Non-repudiation — Ed25519 over each event_hash; the key never has to leave your infrastructure
  • External time — RFC 3161 anchoring: only a 32-byte head hash ever leaves
  • Offline verification — the verifier speaks JSON + openssl ts, no API to trust
  • Undecidable ≠ clean — unverifiable states are named first-class, never folded into OK

Not

  • Not a blockchain — one issuer, one verifier, no consensus tax (ADR 001)
  • Not an observability tool — Langfuse-style logs are for debugging and stay rewritable; this is for proof
  • Not a certification — a building block that states its perimeter instead of overselling it (threat model)
  • Not multi-tenant SaaS — self-hosted, zero telemetry, one SQLite file per journal

§Install

Python ≥ 3.11, MIT, zero telemetry. The ML guardrail engine ships inside the wheel (FR + EN detectors, ~250 KB each) — no model download at runtime.

pip install noirebox        # core: journal + API + guardrail + verifier deps
pip install noirebox[pdf]   # + PDF attestation export (reportlab)
pip install noirebox[hsm]   # + PKCS#11 key custody (python-pkcs11)

Or Docker (image includes the ML engine):

docker run -p 8768:8768 ghcr.io/noirebox/noirebox:latest
# API + OpenAPI docs on http://127.0.0.1:8768/docs — data persists in ./data

Or from source (venv + deps + tests + API):

git clone https://github.com/noirebox/noirebox && cd noirebox
./start.sh

§Quickstart

# 1 — run the API
noirebox serve                # http://127.0.0.1:8768 — interactive OpenAPI at /docs

# 2 — seal an event (auth off by default; enable with NOIREBOX_CLIENTS)
curl -X POST http://127.0.0.1:8768/api/v1/events \
  -H 'Content-Type: application/json' \
  -d '{"type":"llm_call","payload":{"model":"gpt-x","prompt_sha256":"…"}}'

# 3 — anchor the chain head with an external TSA witness (RFC 3161)
curl -X POST http://127.0.0.1:8768/api/v1/anchors

# 4 — export the full dossier
curl -s http://127.0.0.1:8768/api/v1/export > export.json

# 5 — verify as a third party, offline (pip install noirebox is enough)
python verifier/verifier.py export.json
# exit 0 = intact & witnesses verified · 1 = broken · 2 = anchoring unproven

One-command demos: make demo (full scene: scan → journal → auditor → caught tampering) · make demo-mcp · make demo-fleet · make demo-tamper-style standalone scripts in demo/.

§Data model

An Event is the only write shape. Types are free-form strings (1–64 chars) — llm_call, llm_output, incident, eval, anchor are conventions, not a closed enum.

FieldTypeConstraint
seqint≥ 1, no gaps, UNIQUE
tsstrISO 8601 UTC, milliseconds
typestr1–64 chars, free-form
payloadobjectarbitrary JSON (GDPR minimization = caller's responsibility)
prev_hash64 hexSHA-256 of event seq-1 ("0"×64 genesis)
event_hash64 hexSHA-256 of the canonical serialization of {seq, ts, type, payload, prev_hash}, UNIQUE
signature128 hexEd25519 over bytes.fromhex(event_hash), instance key

Canonical serialization — any third-party reimplementation must produce the same bytes:

json.dumps(obj, sort_keys=True, separators=(",", ":"), ensure_ascii=False).encode("utf-8")

The key is Ed25519, PEM PKCS8, chmod 600, created at database init (<db>.key). The public key alone is enough to verify. Where that key lives is pluggable — see custody.

Auth (ADR 004) — enabled only if NOIREBOX_CLIENTS is set: 1-hour JWT HS256, 60 req/min per client (sliding window, 429 + Retry-After), constant-time secret comparison. Errors: 401 (missing/invalid token) · 422 (Pydantic) · 429 (quota) · 503 (engine unavailable, actionable message) · verification failures always carry the exact seq.

§Receipts & sealed payload schemas

Beyond free-form events, subsystems seal versioned payload schemas into the same journal. Each schema version is a contract; the reconciliation layer assembles verdicts from them.

SchemaSealed byCarries
receipt/0.2.2any writerjudged_by (an llm judge requires spec_hash — it read its sealed spec, or the seal refuses), reason, optional requirement_ref
decision/0.1any writerdecision receipts (ADR 028): the System One layer (/v1/systemone) under seal — state as digest, question set hash-bound to its sealed spec (spec_hash required, no exception path), the full distribution, the engine's doubt (label_mass, argmax_is_label) verbatim
admission/0.1any writer · noirebox seal-admissionadmission receipts (ADR 026): the promotion itself — Lin's four invalid transitions named, the never-bases refused at seal time, decision fails closed (admitted | denied | admission_undecidable | admission_check_not_run)
writer/0.1the registrarknown-writers registry: public_hex → domain, declared_by — resolved against the PINNED registrar key (out-of-band); non-registrar entries can't vote; a key under two domains = registry_duplicate_undecidable, never first-wins
registry-disclosure/0.2the reportregistrant + evidence grade — disclosure, never violation; never touches clean_pass
retention/0.1noirebox seal-retentionprune / migrate / policy-change / restore — retention changes are custody events journaled like any other, not ops-layer edits

Named states, never silence: admission_gap · decision_contradiction · label_not_argmax · unverified_label · independence_undecidable · label_llm_call_mismatch · registry_duplicate_undecidable · scope_check_not_run — an undecidable outcome is never reported as clean, and a skipped check is reported as skipped.

The doctrine behind these schemas — who may judge what, and which verdict outranks which — is written up as the authority ladder (ADR 019–022).

§Verification contract

verifier/verifier.py — strict order, first failure wins, never contacts the server (openssl only):

  1. seq of event n equals n — no gaps, no duplicates
  2. prev_hash equals event_hash of event n−1
  3. event_hash equals the recomputed canonical SHA-256
  4. signature valid for the export public key
  5. Attestation: head_seq = event count, head_hash = last event_hash, signature valid on the canonical summary
  6. Each anchor event: referenced head consistent with the chain, RFC 3161 token verified (openssl ts -verify) against that hash and the embedded TSA certificate
ExitMeaning
0INTACT — chain valid and every witness token verified
1BROKEN — first chain/signature break + exact location
2ANCHORING UNPROVEN — a witness token could not be verified (missing openssl/ots, timeout). Report field: unverifiable_witnesses. Accept explicitly with --allow-unverified-witnesses (0.21.0, NB-02: undecidable is never clean — including inside the tool that enforces the doctrine)

TSA roots for public witnesses are pinned in the repository (verifier/tsa_roots/) — the auditor never trusts a certificate the operator ships. The auditing machine needs pip install noirebox, nothing else.

§Key custody & signing

Every signer answers the same interface — .sign() + .public_hex() — so custody can move without touching callers:

SignerKey livesNotes
KeyPairPEM file, chmod 600default; fine when process and disk are one trust domain
SocketSignerkeyholder daemon, over a unix socketsigns bytes, never reveals the key, no export operation; --allow-uid peer check fails CLOSED where the peer uid isn't checkable (0.15.0)
P11SignerPKCS#11 token, non-extractable--ensure-key imports the existing journal key — continuity, not rotation; public hex doesn't move (0.16.0, noirebox[hsm])

Custody disclosure — the journal states its own proof grade:

  • noirebox custody-grade prints witness = min(authoring, retention): a journal is only as provable as the weaker of "was the writer's key in custody at seal time" and "was the retention path itself journaled"
  • noirebox seal-retention --action prune|migrate|policy-change|restore — retention operations become first-class sealed events
  • Custody vs anchoring are different trust boundaries and are disclosed separately (ADR 022)
  • Post-quantum evidence is staged as hybrid signing behind the signer interface — classical Ed25519 stays the trust anchor while a PQ sibling rides along (ADR 027)
  • The pinned hardware root remains the deployer's call — stated in the threat model, not hidden

§Anchoring & fleet

A journal that dates itself proves nothing — that's the suspect writing its own report. Anchoring lets an external Timestamp Authority sign "I received hash X at time T". Only the 32-byte head hash ever leaves. A regenerated journal shows a head the old token doesn't cover, and a backdated token is arithmetically impossible — this is the control that catches an operator with the private key.

Witness layers you choose

LayerTrustSetup
Qualified eIDAS TSA (Universign, Certigna…)legal presumption of date + integrity (eIDAS art. 41)point a profile at the endpoint
Public TSAs (DigiCert, FreeTSA…)independent organizations; roots pinned in this repoNOIREBOX_TSA_PROFILES
OpenTimestamps / Bitcoinforging means redoing the network's proof of work; verifying ≈ 30 µsots client in PATH
Self-hosted OpenSSL TSAown root + leaf chain, 0 €, works offlinemake tsa

The anchor event payload carries head_seq, head_hash, the primary RFC 3161 token (tsr, base64 DER), the TSA cert bundle (tsa_cert_pem) and the full witness list (tokens — one token per profile + OTS receipts).

Fleet hub

One seal for the whole fleet: the heads of N journals form a Merkle tree, a single TSA seal covers them all, and each member proves its place with ~11 hashes — verified offline. noirebox fleet-anchor seals it, fleet-verify checks one member, fleet-status checks every member (exit 0 all covered / 1 alarm, --json for alerting), fleet-watch runs that on a cadence with optional re-anchoring (--reanchor shrinks the falsifiable window to the interval) and webhook alarms. The hub sees 32-byte hashes, never your events.

§Guardrails

Prevention is pluggable; proof is universal. Already running Lakera, Llama Guard, your own LLM-judge? Keep them — a guardrail is just another event source, and its verdicts become tamper-evident instead of living in rewritable logs.

EngineHowLatency (7 lines)
regexbilingual FR/EN patterns compiled at load; score = fixed severity0.21 ms
mlTF-IDF (1–2 word + 3–5 char grams) + logistic regression; FR + EN detectors ~250 KB each in the wheel; threshold 0.5, granularity = line10.3 ms
tieredregex + ML first; a local LLM judge (default qwen2.5-coder:3b, JSON-pinned, temperature 0) only pays for doubt (ADR 015/016)ml cost + judge on disagreement

Incident contract — same shape from every engine:

{
  "category": "instruction_override|data_exfiltration|pii_request|tool_abuse",
  "score": 0.94,
  "excerpt": "…≤ 120 chars…",
  "start": 214, "end": 305
}

Honest failure modes: unparsable judge output → 503, never a manufactured incident; verdicts outside the taxonomy are dropped; measured false negatives are non-zero and tracked. The bundled detector is a working example of the plugin contract — swappable by design (ADR 003: Meta's Prompt Guard evaluated and declined, integration path documented).

Agent hooks & editor

  • noirebox hook tool-use / session-end — seal one tool action (PostToolUse) or the full session transcript (SessionEnd) from hook JSON on stdin; best-effort by design (ADR 013)
  • noirebox seal-trajectory --rollout <dir> — seal a coding agent's model trajectory (model-io JSONL): per-line digests only, never the payload (ADR 012)
  • VS Code / Cursor extension (also on Open VSX) — journal + verify from the editor; versioned separately from the package
  • ZCode / Claude Code plugin — plugins/claude + plugins/noirebox in-repo

Operations

  • noirebox export-siem --format cef|otlp --since N — CEF (ArcSight) or OpenTelemetry JSON, tail-only with --since
  • noirebox audit-pack <outdir> — one folder for the auditor: export + verifier report + the Annexe IV §2(f) logging description (ADR 010)
  • noirebox replay <meeting_id> — rebuild the decision timeline from sealed evidence; refuses if the chain doesn't verify first ("replay refuses theater")
  • noirebox reconcile --config invariants.json --journal-report --fail-on-findings — invariants over the journal, CI-friendly exit 2
  • noirebox crosschain --journal a=path … — consumption edges across journals, partial order, fan-in (ADR 024)
  • noirebox toolset-pin --server S --tools tools.json --reviewed-by NAME --check --fail-on-drift — MCP tool descriptions are instructions: pin the baseline, diff on session start (ADR 025)
  • Built-in dashboard (heatmap, traffic radar) on the service; Grafana JSON in docs/grafana-dashboard.json

§Security & honest limits

The adversary model, trust boundaries and residual risks live in the threat model; the security baseline and scan methodology in SECURITY-BASELINE.md. Report vulnerabilities per SECURITY.md — please don't open public issues for them.

Known limits, assumed and tracked:

  • Payloads are not encrypted — GDPR minimization is the caller's responsibility
  • Pinned hardware root of custody is still open; the published attestation is the countermeasure until then
  • Probabilistic guardrail — measured false negatives are non-zero
  • Single-process append lock — sharding/scaling not targeted
  • 0.21.0 residual: re-hash detection stays a versioned-format decision (NB-05 compatible half)
