## Le commentaire maker (premier post de slabb)

```markdown
I'm the author. NoireBox is a flight data recorder for AI agents: every
decision an agent takes — tool calls, LLM calls, verification events — is
sealed into an append-only SQLite journal where each event is hash-chained
and signed, and the chain head is anchored to external witnesses:
OpenTimestamps (compute-grade, anchored in bitcoin's ledger) plus RFC 3161
timestamp authorities with pinned roots.

The point is that last layer. The EU AI Act (art. 12: automatic event
logging, high-risk deadlines Dec 2027) and GDPR art. 5.2 require
accountable logs — but a log or a git history is editable by whoever holds
the disk, and self-hosted signing doesn't close that gap: the operator can
always re-sign. So NoireBox anchors the chain outside the operator's own
trust boundary, and ships a standalone verifier: hand an auditor
`export.json` and they recompute the whole chain and check every timestamp
themselves, without access to your server or your keys.

It ships as `pip install noirebox` (FastAPI server + CLI), a Docker image,
an MCP server so an agent seals its own decisions from one config block, a
three-stage guardrail for poisoned transcripts (regex → trained micro-model
→ a local LLM judge, all sealed into the same journal), AI-Act-shaped event
builders, and an audit-pack generator that renders the art. 12(3) mapping
from the journal itself. MIT.

One self-demonstrating detail: since v0.7 the agent that built this repo
seals its own tool calls and its own per-call model logs into the repo's
journal — the flight recorder recorded its own construction, and the
shipped verifier checks that log the same way it would check yours.

What it deliberately is not: a detector. It proves what was sealed and
when — not whether the content is true.

Quick look without installing anything: `demo/demo_tamper.py` — one SQLite
UPDATE, the chain explodes.
```

## Munitions (réponses préparées — une seule réponse par question)

### 1. « How much of this is AI-written? » / vibe-coded

Répondre **une fois**, factuel, sans défensive, puis laisser le verifier
parler. Jamais de 2e réponse au troll.

```markdown
Yes, written with AI agents under my direction. The journal in the repo is
the actual log of those sessions, and the shipped verifier lets you check
the journal wasn't altered afterwards. That's literally the product. Even
the published test count is generated from pytest by
tools/sync_test_count.py — the number drifted three times by hand before
that, which is the failure mode the tool exists against.
```

### 2. « What about model collapse / training on synthetic data? »

```markdown
Related: the model-collapse literature asks for exactly this. Shumailov
et al., Nature 631 (2024) names the gap — "it is unclear how content
generated by LLMs can be tracked at scale" — and proposes "community-wide
coordination to ensure that different parties involved in LLM creation and
deployment share the information needed to resolve questions of
provenance." That's a tamper-evident provenance registry. ADR 011 in the
repo documents two event conventions (content_provenance,
ingestion_decision) and demo/demo_provenance.py shows the interesting
part: since every seal is timestamped and anchored, a corpus batch that
includes a hash sealed earlier as "ai-agent" is provable recursive
training, even if the crawler never consulted the registry. Honest scope:
it proves declared provenance; it does not detect synthetic text.
```

### 3. « Git / plain logs already do this »

```markdown
Git gives tamper-evidence against strangers, not against the operator:
whoever owns the repo can rewrite history and re-sign, and nothing
external proves which version existed at time T. The layer NoireBox adds
is anchoring the chain head with third parties (OpenTimestamps → bitcoin
ledger; RFC 3161 TSAs whose roots are pinned in the verifier), so an
auditor's recomputation fails loudly if anything — timestamps included —
was rewritten. One anchor also seals the whole past: the queue between
anchors is the only window where edits could hide, and exports expose it.
```

### 4. « Why not blockchain? »

```markdown
It reads one instead of running one: OpenTimestamps batches your hash into
bitcoin's block headers, so the consensus part is outsourced — no token,
no node; the verifier checks a merkle proof against a public header. The
RFC 3161 layer on top is the eIDAS-friendly one: qualified TSAs get legal
presumption in the EU.
```

## Receipts (ce que n'importe quel visiteur peut lancer)

```bash
pip install noirebox                                   # 0.8.0 sur PyPI
docker run -p 8768:8768 ghcr.io/noirebox/noirebox:latest
.venv/bin/python demo/demo_tamper.py                   # la thèse en une démo
curl -s http://127.0.0.1:8768/api/v1/export > export.json
.venv/bin/python verifier/verifier.py export.json      # exit 0 = chaîne intacte
# variante tout-CLI depuis un pip install :
noirebox seal note '{"hello": "journal"}' && noirebox verify
noirebox audit-pack ./audit                            # le dossier auditeur complet
# le juge LLM local (optionnel, ~1 Go une fois) :
make judge-pull && make demo-judge
```
